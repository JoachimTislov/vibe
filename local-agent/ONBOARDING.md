# Onboarding

This guide takes a new operator from a clean checkout to a local agent that
can answer through the terminal, Neovim, Slack, Telegram, or MCP. The core is
local and private; client processes own model, MCP, and platform connectivity.

## 1. Install prerequisites

Install these before running setup:

- Go 1.25 or newer.
- An OS keychain. On Linux this normally means an unlocked Secret Service
  keyring in the desktop session where the agent runs.
- A model provider: a local Ollama server, or a trusted executable that speaks
  the CLI model protocol described below.
- Neovim if you want the editor client or the complete E2E suite.
- The official Slack CLI only if Slack is enabled:
  [slackapi/slack-cli](https://github.com/slackapi/slack-cli).
- `telegram-cli` from [vysheng/tg](https://github.com/vysheng/tg) only if
  Telegram is enabled. It must be built with JSON and libconfig support.

Build the gateway from the checkout:

```sh
make build
```

The binaries are written to `bin/`. The project does not install or modify
system services automatically.

## 2. Prepare a model

The default is Ollama at `http://127.0.0.1:11434` with `qwen3:8b`.

```sh
ollama serve
ollama pull qwen3:8b
```

You can select another local Ollama model during setup. A remote model must
expose the Ollama `/api/chat` request/response shape and use HTTPS. Its bearer
key is entered into setup and stored in the OS keychain; it is never written
to `config.local.json`.

The `cli` provider is useful for a local wrapper, including an ACP bridge that
you adapt to this simple process boundary. Setup accepts a fixed JSON argv array.
The process receives one non-streaming Ollama-shaped chat request on stdin and
must write a response such as:

```json
{"message":{"role":"assistant","content":"reply"}}
```

Tool calls use `message.tool_calls[].function.name` and
`message.tool_calls[].function.arguments`. This is an explicitly configured
trusted program, not an arbitrary shell command generated by the model.

## 3. Install the selected platform CLIs

### Slack

Install and authenticate the official CLI using its current instructions. The
gateway invokes only `slack api`; it does not use a second Slack SDK or CLI.

Create or install the Slack app in the workspace and grant the scopes needed
for the conversations you select. The adapter calls `auth.test`,
`conversations.history`, `conversations.replies`, and `chat.postMessage`, so
the token must be able to read those conversations and post replies. Private
channels also require membership.

Choose one token mode:

- Personal mode: a scoped OAuth user token beginning with `xoxp-`.
- Bot mode: a bot token beginning with `xoxb-`.

Run `slack login` for the CLI's own development authentication if requested by
the Slack CLI. This is separate from the token entered into `agent setup`.
Never put either token in a command line, JSON file, shell history, or Git.

### Telegram

Build the selected upstream `telegram-cli` with JSON and libconfig support.
`vysheng/tg` is a legacy compatibility choice: it can build and run its
interactive CLI flow, but it is not a modern, actively supported Telegram
SDK. For a long-lived deployment, review a maintained MTProto client such as
[gotd/td](https://github.com/gotd/td) before replacing this adapter contract.
The following build works with the legacy source on a current OpenSSL system
by selecting libgcrypt instead of the bundled OpenSSL path:

```sh
git clone --recursive https://github.com/vysheng/tg
cd tg
./configure --disable-openssl --disable-liblua --enable-json --enable-libconfig
make COMPILE_FLAGS='-std=gnu11 -fcommon -O2 -DHAVE_CONFIG_H -Wall -Wextra -Wno-deprecated-declarations -Wno-unused-parameter -fno-strict-aliasing -fno-omit-frame-pointer -fPIC'
```

The build needs readline, libevent, jansson, libconfig, zlib, and libgcrypt
development packages. Put `telegram-cli` on `PATH`, or enter its absolute
path during setup.

Personal and bot accounts use separate Telegram profiles. A profile contains
authentication state and must be private. The gateway creates only a missing
profile config; `telegram-cli` owns the login/session files.

## 4. Run interactive setup

From the gateway checkout:

```sh
./bin/agent setup --config config.local.json
```

Setup is safe to re-run. It asks for:

1. Enabled clients: `local`, `slack`, `telegram`, and/or `mcp`.
2. A principal ID and the private core Unix socket path.
3. The model provider and model/command details.
4. Slack mode, owner user ID, allowed channel or DM IDs, and a masked token.
5. Telegram mode, an absolute private profile path, owner numeric ID, and
   allowed peers such as `user:123`, `chat:123`, or `channel:123`.
6. Whether MCP operations are enabled, which server to connect to, and which
   `server__tool` names are allowed.

MCP tools are disabled by default. If enabled, every tool call still pauses at
the core approval gate. A local MCP server is entered as a JSON argv array,
not a shell pipeline. A remote MCP endpoint must use HTTPS, except for a
loopback development endpoint; bearer credentials are stored in the keychain.

The resulting `config.local.json` contains routing and key names, not secret
values. It is written with mode `0600`, is ignored by Git, and the loader
rejects a non-private or non-regular config file. Keep the Telegram profile
directory private as well.
The core also refuses a socket whose parent directory is group/world-readable;
the default socket directory is created privately for you.

## 5. Check the installation

Run the dependency check before starting clients:

```sh
./bin/agent doctor --config config.local.json
```

`doctor` checks the selected executable flags, model executable, keychain
token type, and Telegram profile permissions. It does not log in, send a
message, or contact a platform account.

If Telegram is enabled, complete its interactive login once:

```sh
./bin/agent login telegram --config config.local.json
```

Finish the phone/code/2FA or bot flow in the upstream CLI, then quit it. For a
personal account, `get_self` can be used in `telegram-cli` to confirm the
numeric owner ID. Do not paste login codes into the project config.

## 6. Start the core and clients

The core must be running before any client connects. Its default socket matches
the default produced by setup:

```sh
# Terminal 1
./bin/coreserver
```

Start any enabled clients in separate terminals:

```sh
# Terminal 2: local terminal client
./bin/agent local --config config.local.json

# Terminal 3: Slack adapter
./bin/agent slack --config config.local.json

# Terminal 4: Telegram adapter
./bin/agent telegram --config config.local.json
```

Running Slack and Telegram together is supported; they are separate client
processes connected to the same core. Stop a client with Ctrl-C. The core keeps
conversation history only in memory and does not promise delivery recovery
after a restart.

### First request

In the local client, type a prompt and press Enter. For scripts, use one-shot
mode:

```sh
./bin/agent local --config config.local.json \
  --prompt 'Summarize the current project'
```

Slack accepts `agent: your prompt` in an allowed channel or DM. Telegram
accepts `/agent your prompt` from the configured owner and peer. Replies stay
in the originating thread/chat.

The planned grocery extension will add explicit `/grocery add`, `/grocery
list`, and `/grocery delete` commands to this same Telegram boundary. It will
use only operator-selected sites and reviewed open-source scrapers, with
approval required for mutations; the current build does not expose arbitrary
web scraping or purchasing.

When a model requests an MCP operation, the client displays an approval. Send
`/approve ID` or `/deny ID` in the local client, `agent: approve ID` or
`agent: deny ID` in Slack, or `/agent approve ID` / `/agent deny ID` in
Telegram. Approvals are bound to the authenticated client session and
conversation; another user or chat cannot approve the action.

## 7. Add Neovim

Add the plugin directory to Neovim's runtime path and point it at the built
client and config:

```lua
vim.opt.rtp:append('/absolute/path/to/local-agent/integrations/neovim')
require('local_agent').setup({
  command = {
    '/absolute/path/to/local-agent/bin/agent', 'local', '--json',
    '--config', '/absolute/path/to/config.local.json',
  },
})
```

Use `:Agent explain this` or select a visual range and run `:Agent`. Replies
open in a scratch buffer. Approval choices appear through `vim.ui.select`;
the plugin never evaluates model output as editor commands.

## 8. Expose the core through MCP

The gateway can also be used as an MCP server by another MCP client:

```sh
./bin/agent mcp --config config.local.json
```

It exposes an `ask` tool over stdio and forwards the request through the same
core, model, MCP catalog, and approval gate. Configure the command in the
calling MCP client as an argv list. Keep the process attached to the calling
client's stdio streams.

## 9. Verify changes and troubleshoot

Run the repository checks after changing configuration or code:

```sh
make fmt
make vet
make test
```

The deterministic E2E suite substitutes only model/platform CLI fixtures; it
does not log into real accounts or send real messages. The optional upstream
gate exercises an unmodified official Slack CLI against a local HTTPS fixture:

```sh
AGENT_SLACK_CLI=/absolute/path/to/slack make test-upstream
```

Common failures:

- **`core rejected client`**: start `coreserver`, then check that the socket
  path, principal ID, and `--config` file match.
- **Model provider failed**: verify Ollama is running and the model name is
  installed, or run the configured CLI manually with a sample request.
- **Slack token missing/type mismatch**: rerun setup and enter `xoxp-` for
  personal mode or `xoxb-` for bot mode; `slack login` alone is not enough.
- **Slack sees no messages**: confirm owner/channel IDs, app membership, and
  history/reply scopes. Polling starts at adapter launch and ignores older
  messages.
- **Telegram profile rejected**: use an absolute path with a private regular
  file and private parent directory; run `agent login telegram` once.
- **Telegram exits immediately**: run the selected upstream CLI's auth/status
  flow interactively and confirm JSON/permanent-ID support with `agent doctor`.
- **MCP tool unavailable**: enable MCP in setup, use the exact advertised
  `server__tool` name, and include it in `allowed_tools`.

For security questions, remember the boundary: the core has no platform or
model credentials, platform adapters invoke only their selected CLIs, and
state-changing MCP operations cannot run without an explicit approval.
